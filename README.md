# Kazik Bot

Игровой Telegram-бот: экономика, казино, PvP, кланы, банк, крипторынок,
навыки, Battle Pass и административная панель. Валюта в игре виртуальная.
Целевая production-версия — Python 3.11, фреймворк — aiogram 3.

## Запуск

1. Создайте окружение: `python -m venv .venv` и активируйте его.
2. Установите зависимости: `python -m pip install -r requirements.txt`.
3. Скопируйте `.env.example` в `.env`, задайте `BOT_TOKEN` и **свой** `CREATOR_ID`.
4. Для разработки используйте `DB_BACKEND=local`, затем `python main.py`.

## Хранение данных и ограничения

- Production: `DB_BACKEND=firestore` и `FIREBASE_JSON` в секретах хостинга либо
  `FIREBASE_KEY_PATH` вне Git. Ошибка подключения не создаёт пустую запасную базу.
- Локальная база — **JSON, не SQLite**. Это backend для разработки, а не эмулятор
  Firestore; его транзакции и batch-операции не дают production-гарантий атомарности.
- `REDIS_URL` включает Redis FSM; `REDIS_MAX_CONNECTIONS` ограничивает пул.
- Запускайте **один polling-процесс/одну реплику**. Блокировки действуют внутри процесса.
- Battle Pass пока хранится отдельно в `BATTLE_PASS_PATH`. Нужен постоянный диск:
  обычная файловая система Hugging Face Space может обнулиться при пересборке.
  Такой JSON нельзя восстановить из Firestore автоматически.
- Баланс использует отложенную запись: при аварийном завершении возможна потеря
  последних неподтверждённых изменений. JSON-прогресс и баланс — не одна транзакция.
- Дуэли хранятся в памяти. Перезапуск во время игры требует проверки незавершённых
  ставок. Неопределённая ошибка выплаты блокирует её автоматическое повторение
  и требует ручной сверки по журналам — слепая компенсация опасна двойной выплатой.

## Безопасность

Удалённое выполнение Python в админ-панели выключено по умолчанию.
`ENABLE_ADMIN_EVAL=true` включает выполнение **с правами процесса бота, без песочницы**;
оставляйте `false`. Ключи передавайте через секрет-хранилище, не через чат или Git.
`.dockerignore` исключает `.env`, Firebase-ключи, данные, тесты и scratch-скрипты.
Контейнер работает не от root. Логи маскируют распространённые токены и пароли в URL;
это дополнительная защита, а не гарантия отсутствия любых секретов в журналах.

## Проверки

```bash
python -m pip install -r requirements-dev.txt
python -m ruff check .
python -m pytest -q --tb=short
python -m pip check
```

`tests/conftest.py` до импорта приложения отключает `.env`, задаёт временные пути
и запрещает внешние подключения. Тесты не используют production-учётные данные.
Регрессии покрывают повторные покупки/награды, гонки дуэли, возвраты при сбое
Telegram, повреждение JSON, маскировку секретов и копирование изменяемых данных.
Проверки не доказывают отсутствие всех ошибок; игровые сценарии дополнительно
проверяйте в отдельном тестовом Telegram-чате.

## Деплой и откат

Workflow `Test and deploy to Hugging Face` устанавливает зависимости, проверяет
совместимость, запускает Ruff и pytest, затем делает обычный fast-forward push
проверенного коммита в Space. Нужен GitHub secret `HF_TOKEN`. Force push не используется.
Расхождение истории останавливает деплой. Секреты бота задаются отдельно в Hugging Face.
`Container build check` вручную проверяет сборку Docker и не изображает деплой в Glitch.

Перед выпуском завершите активные игры и сохраните данные. После запуска проверяйте
readiness приложения, а не только успешную сборку. Откат кода: `git revert` нужного
коммита и обычный push в `main` с теми же проверками. Откат кода не откатывает данные.
