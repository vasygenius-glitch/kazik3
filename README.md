# Kazik Bot

Игровой Telegram-бот: экономика, казино, PvP, кланы, банк, крипторынок,
навыки, Battle Pass и административная панель. Валюта в игре виртуальная.
Целевая production-версия — Python 3.11, фреймворк — aiogram 3.

## Казик V2 — Mini App прямо в группе

Казино сыроежек внутри Telegram: открывается кнопкой из чата и работает с экономикой
**только этого чата**. Старые команды (`/bonus`, `/bj`, кланы, банк…) не меняются,
баланс общий.

- **Игры:** Блэкджек, Слоты, Кости, Напёрстки, «Тихая охота» (мины), Баккара,
  Видео-покер, КНБ против ИИ-оракула и Колесо дня.
- **Общие столы чата:** Краш, Рулетка, Складчина и Дуэли — все видят один раунд,
  ставки соседей и результат в реальном времени.
- **Зал:** кто сейчас в приложении и во что играет (аватар + имя, без Telegram ID),
  лента крупных выигрышей, бонус, работа, «дело» и премии с анимациями.
- **Зачем играть, а не только собирать бонус:** «огонёк» (+5% к следующему бонусу
  за каждые 10 ставок за день, до +25%), задания дня с наградами, кешбэк с оборота,
  лига недели с призовым фондом (0,5% оборота + комиссия PvP), уровни и достижения,
  анонсы больших выигрышей в чат.
- **Честно:** исход считается только на сервере, отдача ~97% (кости/краш/мины ≈97%,
  рулетка 97,3%, слоты 96,6%, баккара 97–99%). VIP, единорог и престиж дают
  повышенный кешбэк, а не подкрутку шансов. Болезни, бан и техрежим действуют как в боте.

### Команды

| Команда | Кто | Что делает |
| --- | --- | --- |
| `/v2` | все | кнопка «Открыть Казик» для этого чата |
| `/v2 on` · `/v2 off` | создатель | включить/выключить V2 **только в этом чате** |
| `/v2 announce on\|off` | создатель | анонсы крупных выигрышей |
| `/v2 status` | все | состояние (создателю — адрес и способ открытия) |

Чат приложения берётся из подписанного токена кнопки (`startapp`), поэтому
из одной группы нельзя попасть в экономику другой. Без токена приложение не
открывается. Ставки общих столов после перезапуска возвращаются автоматически.

### Настройка (один раз)

1. Space на Hugging Face должен быть **публичным** — Telegram открывает
   `https://<space>.hf.space/app/` без авторизации HF. Секреты Space остаются скрытыми.
2. В @BotFather: *Bot Settings → Configure Mini App → Main Mini App* и адрес
   `https://dictortanibani-dicasdf.hf.space/app/`. Тогда кнопка в группе открывает
   приложение сразу. Вариант: `/newapp` с короткой ссылкой и переменная
   `V2_APP_SHORT_NAME`. Без настройки кнопка ведёт в личку с ботом.
3. В группе создатель пишет `/v2 on`.

Переменные: `V2_WEBAPP_URL` (по умолчанию из `SPACE_HOST`), `V2_APP_SHORT_NAME`,
`V2_MAX_BET`, `V2_AVATAR_DIR`. `V2_DEV=1` — только для локального стенда, не в production.

### Разработка

`python -m v2.devserver 8090` поднимает API и фронтенд на 127.0.0.1 с тестовым
чатом и игроками-ботами (ставят на столах, принимают дуэли) — ссылка печатается
при старте. Фронтенд — `v2/web/` (ES-модули, без сборки), API — `v2/api.py`,
игры — `v2/games/`, деньги — `v2/wallet.py`, прогресс — `v2/profile.py`.

## Запуск

1. Создайте окружение: `python -m venv .venv` и активируйте его.
2. Установите зависимости: `python -m pip install -r requirements.txt`.
3. Скопируйте `.env.example` в `.env`, задайте `BOT_TOKEN` и **свой** `CREATOR_ID`.
4. Для разработки используйте `DB_BACKEND=local`, затем `python main.py`.

## Хранение данных и ограничения

- Production: `DB_BACKEND=firestore` и `FIREBASE_JSON` в секретах хостинга либо
  `FIREBASE_KEY_PATH` вне Git. Ошибка подключения не создаёт пустую запасную базу.
- Локальная база — **JSON, не SQLite**. Это backend для разработки, а не эмулятор
  Firestore; его транзакции и batch-операции не дают production-гарантий атомарности.
- `REDIS_URL` включает Redis FSM; `REDIS_MAX_CONNECTIONS` ограничивает пул.
- Запускайте **один polling-процесс/одну реплику**. Блокировки действуют внутри процесса.
- Battle Pass пока хранится отдельно в `BATTLE_PASS_PATH`. Нужен постоянный диск:
  обычная файловая система Hugging Face Space может обнулиться при пересборке.
  Такой JSON нельзя восстановить из Firestore автоматически.
- Баланс использует отложенную запись: при аварийном завершении возможна потеря
  последних неподтверждённых изменений. JSON-прогресс и баланс — не одна транзакция.
- Дуэли хранятся в памяти. Перезапуск во время игры требует проверки незавершённых
  ставок. Неопределённая ошибка выплаты блокирует её автоматическое повторение
  и требует ручной сверки по журналам — слепая компенсация опасна двойной выплатой.

## Безопасность

Удалённое выполнение Python в админ-панели выключено по умолчанию.
`ENABLE_ADMIN_EVAL=true` включает выполнение **с правами процесса бота, без песочницы**;
оставляйте `false`. Ключи передавайте через секрет-хранилище, не через чат или Git.
`.dockerignore` исключает `.env`, Firebase-ключи, данные, тесты и scratch-скрипты.
Контейнер работает не от root. Логи маскируют распространённые токены и пароли в URL;
это дополнительная защита, а не гарантия отсутствия любых секретов в журналах.

## Проверки

```bash
python -m pip install -r requirements-dev.txt
python -m ruff check .
python -m pytest -q --tb=short
python -m pip check
```

`tests/conftest.py` до импорта приложения отключает `.env`, задаёт временные пути
и запрещает внешние подключения. Тесты не используют production-учётные данные.
Регрессии покрывают повторные покупки/награды, гонки дуэли, возвраты при сбое
Telegram, повреждение JSON, маскировку секретов и копирование изменяемых данных.
`tests/test_v2_*.py` проверяют Казик V2: подпись initData и токенов чата, отдачу
игр, правила карт, общие столы, возвраты ставок и HTTP API.
Проверки не доказывают отсутствие всех ошибок; игровые сценарии дополнительно
проверяйте в отдельном тестовом Telegram-чате.

## Деплой и откат

Workflow `Test and deploy to Hugging Face` устанавливает зависимости, проверяет
совместимость, запускает Ruff и pytest, затем делает обычный fast-forward push
проверенного коммита в Space. Нужен GitHub secret `HF_TOKEN`. Force push не используется.
Расхождение истории останавливает деплой. Секреты бота задаются отдельно в Hugging Face.
`Container build check` вручную проверяет сборку Docker и не изображает деплой в Glitch.

Перед выпуском завершите активные игры и сохраните данные. После запуска проверяйте
readiness приложения, а не только успешную сборку. Откат кода: `git revert` нужного
коммита и обычный push в `main` с теми же проверками. Откат кода не откатывает данные.


## Безопасная работа с админ-панелью

- Все защищённые обработчики проверяют права создателя. Ввод чисел проверяет границы и не принимает NaN/Infinity; фото и другие нетекстовые сообщения не ломают текстовые диалоги.
- Переход по кнопке отменяет предыдущий ввод. Опасные подтверждения привязаны к оператору, сообщению и действию, действуют 120 секунд и используются один раз. Сериализация действий работает внутри одного процесса; несколько одновременно запущенных polling-процессов не поддерживаются.
- Сброс FSM очищает состояние игрока в выбранном чате; это не отмена всех игровых сессий в памяти. `/reset_game USER_ID CHAT_ID` требует явного чата.
- При удалении банка возврат вклада и его обнуление записываются одним обновлением документа под блокировкой игрока. Уже возвращённый вклад повторно не начисляется. Удаление всего банка по-прежнему не является общей транзакцией: при ошибке проверьте оставшихся вкладчиков и состояние банка.
- Перед глобальным сбросом или восстановлением включите техрежим, дождитесь завершения активных игр и не выполняйте параллельных изменений экономики. Техрежим не останавливает уже выполняющиеся задачи и не является полной блокировкой всех фоновых записей.
- Копия содержит только `users`, `banks`, `clans` в выбранных/разрешённых чатах. Она НЕ включает глобальные настройки (в том числе курсы криптовалют), локальный Battle Pass JSON, секреты и игровые сессии. Для полного аварийного восстановления нужен отдельный экспорт Firestore и постоянного диска.
- Перед созданием копии сохраняется отложенный пользовательский кэш. Копии имеют уникальные ID; первая автоматическая попытка — через 60 секунд после старта, затем каждые 24 часа. Ошибка очистки старых копий не отменяет уже созданный снимок.
- Формат и размер всей копии проверяются до восстановления. Лимиты: 16 MiB распакованного JSON и 900 000 символов нового base64-пакета в документе Firestore. Более крупные базы требуют внешнего хранилища, а не усечения данных.
- Восстановление сначала создаёт защитный снимок, записывает входящие документы и только затем удаляет отсутствующие в копии. Восстановление нескольких документов НЕ атомарно: при сетевом сбое возможен частичный результат. Оставьте техрежим включённым, проверьте журнал и защитный снимок; не повторяйте финансовые операции вслепую.
- Старые или неполные копии, не содержащие явно все три раздела каждого чата, отклоняются без восстановления. Тесты выполняются на временных данных, с отключённым доступом к внешним сервисам.
